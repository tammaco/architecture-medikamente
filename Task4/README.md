# Задание 4. Оценка узких мест при миграции

1. Анализ текущей системы и целей миграции

|Компонент|Текущая реализация|Проблемы|
|-|-|-|
|Хранилище данных|Excel-файлы на общем диске, файловая 1С|Нет целостности, ручной ввод, дублирование, нет версионности|
|Бизнес-логика|Ручные процессы|Зависимость от людей, ошибки, нет документации|
|Интеграции|OLE между 1С:Бухгалтерия и 1С:Торговля, ручной обмен файлами|Хрупкость, ошибки, нет автоматизации|
|Безопасность|Общий диск, нет шифрования, нет разграничения|Утечки, нарушение 152-ФЗ|
|Инфраструктура|Физические серверы, общий диск|Масштабируемость, отказоустойчивость, бэкапы|

3. Основные категории и рекомендации

|Проблема|Рекомендации|Приоритет|
|-|-|-|
|Недостаточная мощность серверов, нет оркестрации, общий диск (SPOF)|Внедрение Kubernetes, переход на MinIO/S3, добавление узлов|Критический|
|Сложность декомпозиции монолита, нет CI/CD|Применение DDD, внедрение CI/CD|Высокий|
|OLE-обмен, ручной обмен с лабораторией, нет API у 1С|Разработка REST API для 1С, внедрение API Gateway и сервиса токенизации| Критический|
|Нехватка навыков Kubernetes, микросервисов, DDD|Обучение, наём DevOps-инженера, создание внутренней документации|Высокий|
|Нет плана миграции, тестирования нагрузки, плана отката|Разработка плана миграции, внедрение нагрузочного тестирования в CI/CD|Критический|
|Шифрование и аудит замедляют работу, управление ключами|Аппаратное ускорение шифрования, кеширование ключей, асинхронное логирование|Высокий|

4. Вывод

В рамках анализа миграции монолитной системы на микросервисную архитектуру выявлены потенциальные узкие места по пяти категориям: инфраструктура, программное обеспечение, интеграция, персонал, процессы и безопасность. Наиболее критичные риски связаны с отсутствием оркестрации (Kubernetes), устаревшими протоколами интеграции (OLE) и недостаточной квалификацией команды.
