# Задание 5. Разработка cutover-плана


## Анализ

Исходя из описания существующей системы, требований к новой архитектуре и бизнес-целей миграции, можно выделить основные характеристики «Медикаменте»:

|Параметр|Текущее состояние (As-Is)|Целевое состояние (To-Be)|
|-|-|-|
|Архитектура|Монолитная, файловая (Excel, 1С)|Микросервисная, контейнеризированная|
|Хранилище|Общий диск, Excel-файлы|PostgreSQL, Data Lake (MinIO/S3)|
|Бизнес-логика|Вручную, в головах сотрудников|Микросервисы|
|Интеграции|OLE между 1С, ручной обмен с лабораторией|REST API, Kafka|

Особенное внимание нужно удить высокой критичности системы (медицинские услуги, платежи, ПДн).

## Оценка стратегий миграции


|Стратегия|Преимущества|Ограничения|Применимость|
|-|-|-|-|
|High-level design (Big Bang)|Быстрый переход|Высокий риск, длительный простой, сложный откат|Нет|
|Parallel run|Минимальный риск, возможность сравнения, постепенный перевод|Двойной ввод данных, синхронизация, высокая нагрузка на сотрудников|Да|
|Branch by abstraction|Постепенный переход, минимальный простой|Сложность реализации|Да|

Рекомендуемая стратегия: Parallel run.

## Поэтапный план миграции

|Этап|Время/Сроки|Ключевые задачи|Ответственные|Риски и меры по снижению|
|-|-|-|-|-|
|Подготовка инфраструктуры|3 - 5 недель|Аренда/покупка ЦОД, найм команды разработки (DevOps (2 чел), Backend (3 чел), Frontend (1 чел), Аналитик (1 чел), DBA (1 чел)), развёртывание и настройка инфраструктуры (K8s, БД, MinIO)|технический директор, бизнес-аналитик|Трудности в найме, затягивание развёртывания - контроль сроков|
|Подготовка данных|1-2 недели|Перевод 1С в клиент-серверный режим, определение основных сущностей для переноса в PostgreSQL, настройка сервера PostgreSQ|бизнес-аналитик, DBA|1С - один сплошной риск, возможная нехватка мощностей ЦОД|
|Разработка API-сервисов для MVP (портал компании и портал для ресепшн)|3-4 недели|Написание Backend и Frontend модулей, развёртывание в тестовой среде, тестирование, выливка в prod-среду, нагрузочное тестирование|DevOps, Backend, Frontend|Затягивание процесса разработки из-за неучтённых сложностей, трудности взаимодействия новой команды - контроль сроков, поддержка команды|
|Пилотный запуск|1 неделя|Выбор пилотной группы (ресепшен + 1 врач), обучение, запуск новой системы в тестовом режиме, сбор ОС, исправление ошибок|DevOps, Backend|Пилот не работает как предполагалось - анализ требований|
|Параллельный запуск|2-3 недели|Запуск новой системы для всех сотрудников (параллельно со старой), двойной ввод данных, ежедневная сверка, мониторинг, оптимизация|DevOps, Backend|Данные не совпадают, производительность приемлема - корректировка ошибок синхронизации, мониторинг нагрузки и производительности, оптимизация|
|Переход|2-3 недели|Перевод записей к врачу, регистарции пациентов - всех сотрудников и клиентов на новую систему|DevOps, Backend, Аналитик|Внезапные ошибки, снижение производительности - мониторинг и анализ логов, исправление ошибок|
|Завершение|1 неделя|Отключение старой системы (кроме архивов), архивация данных старой системы, финальное тестирование, документирование|DevOps, Backend , DBA|Архив слишком большой - наращивание мощностей|

## План отката

|Инцидент|Действие|Ответственный|Сроки|
|-|-|-|-|
|Потеря данных при миграции из файлов в БД|Перепроверка всех процедур на маленькой выборке, исправление|DevOps, DBA|1 день|
|Проблемы с интеграцией 1С|Тщательное тестирование API-адаптера|DevOps, DBA|1 день|
|Сбой новых сервисов до вывода старой - критическая ошибка, блокирующая работу > 30 минут|Переключение на старую версию|DevOps|30 минут|
|Данные не совпадают при параллельном запуске|Остановка тестирования, переключение на старую версию, анализ ошибок|DevOps, Аналитик|2 дня|
|Медленная работа новой системы|Анализ логов, горизонтальное масштабирование|DevOps|2 дня|
