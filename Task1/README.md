# Задание 1. Анализ безопасности системы

## Список проблемных зон

|Зона|Описание проблемы|Риск|
|-|-|-|
|Общий диск (File system)|Неограниченный доступ всех сотрудников ко всем файлам. Нет шифрования. Нет журналирования|Утечка всех данных|
|Excel-файлы с ПДн|Файлы хранятся в открытом виде. Нет парольной защиты. Нет ограничений на копирование.|Утечка ПДн|
|1С в файловом режиме|База данных 1С не шифруется. Доступ без разграничения.|Финансовые махинации, утечка|
|Отсутствие шифрования|Нигде нет шифрования|Перехват данных|
|Отсутствие обезличивания|Данные используются в исходном виде во всех процессах|Нарушение 152-ФЗ|
|Ручная передача данных|Файлы передаются на флешках, по почте без защиты|Утечка|
|Нет политик доступа|Нет ролевой модели|Утечка|
|Нет регулярного аудита|Нет проверок, кто и когда обращался к данным|Невыявление утечек|

## Список данных для защиты

|Данные|Шифрование|Обфускация|Обезличивание|
|-|-|-|-|
|ФИО|При хранении и передаче|В логах и отчетах|В аналитике (замена на ID)|
|Телефон, email|При хранении и передаче|В логах и отчетах|В аналитике|
|Дата рождения|При хранении|В отчетах (скрытие года)|В аналитике (возрастные группы)|
|Адрес, место работы|При хранении и передаче|В общих отчетах|В аналитике|
|Медицинские диагнозы|При хранении и передаче|Не применять|В аналитике (коды МКБ, без связи с ФИО)|
|Результаты анализов|При хранении и передаче|Не применять|В аналитике (агрегированные данные)|
|Финансовые данные|При хранении и передаче|В отчетах для руководства|В аналитике (агрегированные)|
|Паспортные данные|При хранении и передаче|Не применять|Не применять (хранятся только в сканах)|

## Механизм тегирования

|Тег|Назначение|Какие данные|
|-|-|-|
|[CONFIDENTIAL]|Строго конфиденциальные данные|Медицинские диагнозы, паспортные данные|
|[PERSONAL]|Персональные данные общего доступа|ФИО, телефон, email|
|[FINANCIAL]|Финансовые данные|Суммы оплат, реквизиты|
|[INTERNAL]|Внутренние документы без ПДн|Товарные накладные, контракты|
|[PUBLIC]|Общедоступные данные|Информация о ценах, режим работы|
|[EXPIRES:YYYY-MM-DD]|Дата уничтожения данных|Сканы контрактов, чеки|

## Список инструментов, способов и мер, которые позволят обеспечить конфиденциальность данных

|Этап потока|Меры|
|-|-|
|Сбор данных|Минимизация форм (Data Minimization), TLS 1.3|
|Передача между системами|TLS для всех соединений, запрет пересылки ПДн почтой|
|Хранение|СУБД PostgreSQL, объектное хранилище документов с шифрованием SSE|
|Доступ|RBAC по ролям (врач, ресепшен, кассир, бухгалтер, кладовщик) и принцип наименьших привилегий|
|Обработка|Маскирование, токенизация платёжных данных, псевдонимизация в аналитике|
|Удаление|Политики retention по тегам; процедура исполнения запроса клиента на прекращение обработки (right to erasure)|
|Резервирование|Шифрованные бэкапы|

Диаграммы потоков данных лежат в [папке](https://github.com/tammaco/architecture-medikamente/Task1/DFD).
Для каждой диаграммы в рамках улучшений добавлен комментарий.
