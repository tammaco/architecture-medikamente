# Задание 6. Классификация данных

## Движок для классификации данных

1. Ingestion Layer
- Пакетный приём данных из всех источников  
- Мониторинг новых файлов
- Буферизация и управление очередями
- Форматирование данных в универсальный формат (JSON)

2. Classification Layer
  - Правила + regex (Rule-Based Classifier)
    - Проверка по шаблонам (ФИО, телефон и т.д.)
    - Проверка по словарям (список диагнозов)
  - ML-Based Classifier
    - Классификация по контексту (медицинский термин, финансовый термин)
    - Классификация по аналогии 
  - Ручная проверка
    - Обязательная ручная перепроверка
    - Обучение, корректировака модели
  - Tagging Service
    - Применение тегов к данным и полям 
    - Теги: [PERSONAL], [CONFIDENTIAL], [MEDICAL], [FINANCIAL], [INTERNAL], [PUBLIC]
- Anonymization Layer
  - Маскирование часи телефонов, email-адресов для ответов из API, логов
  - Токенизация (замена ФИО на ID (UUID))
  - Агрегирование (группировка по возрасту, диагнозам)
- Data Lake

## Метрики для оценки эффективности классификации данных

|Метрика|Описание|Целевое значение|
|-|-|-|
|Precision (Точность)|Доля правильно классифицированных записей среди всех, отнесённых к классу|> 95%|
|Recall (Полнота)|Доля правильно классифицированных записей среди всех записей, которые должны быть отнесены к классу|> 98%|
|F1-Score|Среднее между Precision и Recall|> 0.96|
|Accuracy|Доля правильно классифицированных записей от общего числа|> 97%|
|Количество ложных срабатываний (FP)|Записи, ошибочно отнесённые к классу (например, PUBLIC → CONFIDENTIAL)	< 1%|
|Количество пропусков (FN)|Записи, которые должны быть отнесены к классу, но не отнесены (CONFIDENTIAL → PUBLIC)|0%|
|Время классификации|Среднее время на классификацию одной записи|< 100 мс|
|Процент ручной проверки|Доля записей, направленных на ручную проверку|< 10%|
